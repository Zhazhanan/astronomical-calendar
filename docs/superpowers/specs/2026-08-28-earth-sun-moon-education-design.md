# 日—地—月与中国历法教学可视化设计

日期：2026-08-28

状态：对话设计已确认，等待书面审阅

## 1. 背景

现有 `tiangan_dizhi_offline.html` 将太阳黄经、天干地支、二十四节气、二十八宿、恒星和简化的地月动画放在同一个 3D 场景中。它可以展示概念，但物理运动、地球视角和历法知识混杂，月球轨道也没有按真实倾角表达。随着公历月份、农历月份、观察地点、昼夜和双口径干支纪年的加入，继续扩充单个脚本会增加坐标不一致、重复计算和难以测试的风险。

本设计把页面改造成教学级、离线、模块化的日—地—月学习工具。核心原则是：同一个绝对时刻只计算一次天文和历法状态，太阳中心场景、地球中心场景、时间轴和知识卡共享同一份结果。

## 2. 目标

页面应帮助用户理解：

1. 地球如何绕太阳公转，地轴倾角如何造成四季与昼夜长度变化。
2. 月球如何沿相对黄道约倾斜 5.145° 的轨道绕地球运行，以及月相、升降交点和日月食对齐条件。
3. 站在地球上观察时，太阳如何沿黄道发生视运动，太阳黄经如何对应二十四节气。
4. 公历 1–12 月、农历月份、朔望月、闰月和二十四节气之间的区别与联系。
5. 干支纪年的春节换年口径和立春换年口径为什么可能不同。
6. 时区、纬度和观察地点如何影响当地日期、太阳高度、昼长与夜长。

## 3. 非目标

本页面不用于：

- 航天任务、专业观测、导航或高精度星历计算。
- 天气、气候预测或占星判断。
- 完全按真实尺度同时绘制天体直径和天体距离；真实尺度会使月球和地球难以看见。
- 在线地理编码、远程星历查询或运行时网络依赖。
- 在当前 3D 场景中保留杂乱的六十甲子连线。

## 4. 已确认的产品决策

- 采用 B1 布局：桌面端两个 3D 场景等宽并排，共享时间轴和下方知识卡。
- 同时提供太阳中心和地球中心两种视角，同一日期同步更新，相机分别控制。
- 采用教学级真实模型，不引入专业星历库。
- 同时显示公历月份和农历月份。
- 同时显示春节换年和立春换年的干支年结果。
- 支持时区选择，默认 `Asia/Shanghai`，同时可使用浏览器本地时区。
- 支持预设城市和自定义经纬度，显示昼夜分界、直射点、太阳高度和昼夜长度。
- 银河、二十八宿和本地星表归入“进阶天文”面板，默认关闭。
- 农历和双口径干支的完整支持范围为 1900–2100 年。

## 5. 架构

### 5.1 离线模块形式

页面必须能够通过双击 `tiangan_dizhi_offline.html` 直接打开。为避免 `file://` 环境下 ES Module 的跨源限制，不使用构建工具，也不依赖开发服务器。各 JavaScript 文件使用经典 `<script>` 顺序加载，并以小型 UMD/IIFE 包装同时支持：

- 浏览器全局命名空间 `window.AstroEducation`。
- Node 测试中的 `module.exports`。

Three.js 和 OrbitControls 继续使用仓库内的本地文件。

### 5.2 文件职责

建议目录结构：

```text
tiangan_dizhi_offline.html
styles/
  astronomy-education.css
js/
  astronomy-core.js
  calendar-core.js
  observer-core.js
  world-state.js
  time-controller.js
  scene-host.js
  heliocentric-scene.js
  geocentric-scene.js
  education-panel.js
  app.js
tests/
  astronomy_core.test.cjs
  calendar_core.test.cjs
  observer_core.test.cjs
  world_state.test.cjs
  test_offline_page.py
```

职责如下：

- `astronomy-core.js`：太阳、地球和月球的教学级位置、轨道、相位与关键角度。
- `calendar-core.js`：公历、农历、二十四节气和两种干支年口径。
- `observer-core.js`：观察地点、太阳高度、方位、直射点、昼长和夜长。
- `world-state.js`：把三个纯计算模块合并成不可变的 `WorldState`。
- `time-controller.js`：绝对时刻、日期跳转、播放暂停、速度、时区和年度时间轴。
- `scene-host.js`：WebGL 渲染器、两个视口、相机、尺寸变化和上下文恢复。
- `heliocentric-scene.js`：太阳中心场景。
- `geocentric-scene.js`：地球中心场景。
- `education-panel.js`：知识卡、图层控件、可访问性和 2D 降级界面。
- `app.js`：应用初始化、事件连接和错误边界，不包含天文公式。

### 5.3 数据流

```text
UTC 绝对时刻 + 时区 + 观察地点
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
   Astronomy   Calendar   Observer
        └─────────┼─────────┘
                  ▼
              WorldState
        ┌─────────┼──────────────┬─────────────┐
        ▼         ▼              ▼             ▼
   太阳中心场景  地球中心场景   共享时间轴     知识卡
```

渲染器和 UI 不自行计算太阳黄经、月相或历法。所有派生值必须来自 `WorldState`，以避免两个场景显示不同结果。

### 5.4 WorldState 主要字段

`WorldState` 至少包含：

- `instantUtc`：唯一的绝对时刻。
- `displayTime`：选定 IANA 时区下的日期和时间。
- `earth`：日心位置、日地距离、自转角、地轴方向、近日点/远日点信息。
- `sun`：地心视位置、黄经、赤经、赤纬、当前与下一个节气。
- `moon`：地心位置、黄经、黄纬、距离、月相、照亮比例、升降交点关系。
- `observer`：经纬度、太阳高度、方位、昼长、夜长和直射点。
- `gregorian`：公历年、月、日及年度进度。
- `lunar`：农历年、月、日、闰月标记、朔望信息。
- `ganzhi`：春节口径和立春口径的干支年。
- `support`：各项计算是否在支持范围内，以及需要展示的警告。

## 6. 天文计算与视觉模型

### 6.1 地球与太阳

采用 JPL 所描述的低精度开普勒轨道思路计算教学级地球位置。这类公式适合不需要完整积分星历的应用。地球轨道显示轻微偏心，并标出近日点和远日点。

地轴相对黄道法线保持约 23.44° 倾角，并在地球公转过程中保持惯性方向。场景必须避免把地轴错误地始终指向太阳。太阳中心场景使用太阳光照地球材质形成昼夜分界。

地球的直径、太阳的直径、月球的直径、日地距离和地月距离分别采用可视化增强比例。场景始终显示“大小与距离非同一真实比例”的图例。

### 6.2 月球

月球轨道相对黄道的平均倾角采用约 5.145°，显示升交点和降交点。教学模型还应表现：

- 椭圆轨道及近地点/远地点。
- 恒星月与朔望月的差异。
- 月相由太阳—地球—月球夹角决定，而不是使用固定贴图切换。
- 交点线随约 18.6 年周期缓慢回归的教学近似。
- 新月或满月接近交点时显示“可能进入食季”的说明，不预测专业级日月食路径。

### 6.3 地球中心视角

地球中心场景显示：

- 黄道、天球赤道和春分 `0°` 基准。
- 地球指向太阳的方向线、太阳黄经圆弧和动态角度标签。
- 太阳和月球的地心视位置。
- 二十四节气的 15° 刻度与名称。
- 月球黄纬、朔望和接近升降交点的状态。

春分、夏至、秋分、冬至分别对应太阳黄经 `0°`、`90°`、`180°`、`270°`。

### 6.4 观察地点

页面内置一组常用城市，但不调用在线地图。用户也可以输入经纬度。观察地点模块输出：

- 当前太阳高度和方位。
- 当日昼长和夜长。
- 太阳直射点纬度与经度。
- 地球表面的观察点标记。
- 当前地点位于昼半球、晨昏线附近或夜半球。

默认地点为北京，默认时区为 `Asia/Shanghai`。地点和时区是两个独立设置；更改地点不会静默改变用户已选择的时区。

## 7. 历法模型

### 7.1 公历

公历行按实际月份天数绘制 1–12 月。闰年规则通过纯函数计算。年度时间轴以选定时区中的公历年为边界。

### 7.2 二十四节气

二十四节气是太阳到达预定黄经位置的时刻，不是固定公历日期。计算模块对每个 15° 目标黄经进行求根，得到节气时刻，而不只用 `Math.floor(longitude / 15)` 近似当前区间。

时间轴显示当年的全部节气时刻；当前节气、下个节气和剩余时间来自相同结果。节气名称以春分 `0°` 为坐标起点，但界面可以按传统顺序从立春开始排列说明。

### 7.3 农历

1900–2100 年使用随项目分发、可测试的离线农历数据和转换逻辑，不把浏览器 `Intl` 输出作为唯一真源。`Intl.DateTimeFormat` 可作为格式化和交叉检查手段。

农历模块必须处理：

- 农历月从朔附近开始。
- 大月、小月和闰月。
- 闰月名称和前后月份顺序。
- 同一公历年时间轴可能跨越两个农历年。
- 超出范围时返回结构化“不支持”结果，而不是近似或伪造日期。

### 7.4 双口径干支年

- 春节口径：农历正月初一进入新的干支年。
- 立春口径：选定时区中的立春节气时刻进入新的干支年。

知识卡始终并列显示两种结果。两种结果不同时，界面高亮差异并解释换年边界；不把任一口径标成唯一正确答案。

## 8. 页面布局与交互

### 8.1 桌面 B1 布局

从上到下依次为：

1. 日期、播放速度、时区、地点和图层控制。
2. 左右等宽的太阳中心与地球中心 3D 场景。
3. 三层共享年度时间轴。
4. 六类知识卡。

两个 3D 场景共享日期，但相机独立旋转和缩放。拖动某个场景不会改变另一个场景的相机。

### 8.2 时间控制

提供：

- 日期和时间选择器。
- “今天”按钮。
- 前一天、后一天。
- 播放和暂停。
- `1 天/秒`、`7 天/秒`、`30 天/秒`。
- 可拖动和缩放的年度时间轴。

播放跨过节气、朔望、春节或立春边界时，短暂停顿并高亮发生变化的卡片。切换时区不改变绝对时刻，只改变当地日期和历法显示。

### 8.3 三层时间轴

- 公历层：按真实天数绘制 1–12 月。
- 节气层：在计算出的准确时刻放置 24 个标记。
- 农历层：按朔到朔绘制农历月，并显示朔、望；实际存在闰月时插入第 13 段并使用独立颜色。

三层使用同一条当前时刻指针。示意图中的月份和日期不得冒充某个真实年份的计算结果。

### 8.4 知识卡

知识卡包括：

1. 当前绝对时刻、北京时间和浏览器本地时间。
2. 太阳黄经、赤纬、日地距离、季节和下个节气。
3. 公历月份、农历月日、闰月、月相和下一次朔望。
4. 春节口径与立春口径干支年。
5. 观察地点、太阳高度、方位、昼夜长度和直射点。
6. “为什么？”动态解释。

“为什么？”卡根据当前 `WorldState` 选择最相关的解释，例如昼渐长、昼渐短、月相变化、节气交界或两种干支年不同，不显示与当前状态无关的固定文案。

### 8.5 进阶内容

默认关闭的“进阶天文”面板包含：

- 银河示意。
- 二十八宿。
- 本地 CSV 星表。

删除不可用的远程星表占位抓取按钮。CSV 输入设置文件大小、最大行数和字段校验；无效行跳过并显示统计。

六十甲子不再以 60 条空间连线显示，改为干支年知识卡、年份查询和可选的纪年轮。独立的 `tiangan_dizhi_cycle.html` 不在本次改造范围内。

## 9. 响应式与可访问性

### 9.1 响应式

- 桌面：双场景并排。
- 平板：双场景上下排列。
- 手机：太阳中心/地球中心标签切换，只渲染当前可见场景。
- 手机时间控制固定在底部，年度时间轴横向拖动。
- 知识卡在手机上使用折叠面板，默认展开“当前时刻”和“为什么？”。

### 9.2 可访问性

- 所有控件支持键盘和明确的焦点样式。
- 场景、时间轴和知识卡使用结构化标题及 ARIA 标签。
- 颜色之外同时使用线型、符号和文字区分轨道。
- 支持 `prefers-reduced-motion`，关闭自动旋转和非必要动画。
- 3D 标签可以单独隐藏，避免视觉拥挤。
- 文字保持高对比度，移动端触控目标不小于常用可访问尺寸。

## 10. 性能

- 桌面使用一个 `THREE.WebGLRenderer` 和两个 scissor viewport 绘制两个场景。
- 手机只渲染当前可见场景。
- 页面隐藏、播放暂停或场景不可见时减少或停止动画帧。
- 根据设备能力限制像素密度、星点数量和轨道细分。
- 纯计算结果按绝对时刻缓存；每帧只更新相机、地球自转和必要的插值，不重复计算整套历法。
- 进阶星空默认关闭，避免首次加载占用过多 GPU 资源。

## 11. 错误与降级

- WebGL 不可用：保留日期控制、2D 时间轴、历法和知识卡，显示“3D 场景不可用”。
- Three.js 或 OrbitControls 加载失败：显示明确依赖错误，不保留黑屏。
- WebGL 上下文丢失：暂停播放，提示重新加载场景，并在恢复后重建资源。
- 农历范围外：轨道继续运行，农历和双口径干支返回结构化范围提示。
- 无效时区：恢复 `Asia/Shanghai` 并显示提示。
- 无效地点：恢复北京坐标并保留用户输入以便修正。
- CSV 星表错误：跳过错误行，报告成功、跳过和失败数量。
- 所有错误在页面内呈现，不只写入控制台。

## 12. 测试策略

实现遵循测试驱动开发。计算模块不依赖 DOM 或 Three.js。

### 12.1 天文单元测试

- 春分、夏至、秋分、冬至的黄经和季节映射。
- 地球椭圆轨道的近日点、远日点和距离变化方向。
- 地轴方向在公转过程中的稳定性。
- 月球轨道倾角、升降交点、朔、上弦、望和下弦。
- 新月/满月接近交点时的食季提示逻辑。

### 12.2 历法单元测试

- 公历闰年和月份长度。
- 1900–2100 年边界。
- 农历大月、小月、闰月、春节前后。
- 立春节气时刻前后。
- 两种干支年相同和不同的日期。
- 已发布权威历书中的代表性节气时刻，允许教学算法规定的误差范围。

### 12.3 地点与时区测试

- 北京时间和浏览器本地时区跨日期边界。
- 春分赤道附近昼夜接近等长。
- 夏至和冬至不同纬度的昼长变化方向。
- 无效时区、经度和纬度的结构化错误。

### 12.4 集成与页面测试

- 同一 `WorldState` 驱动两个场景、时间轴和知识卡的一致性。
- 播放、暂停、速度、日期跳转和边界高亮。
- 桌面、平板和手机布局切换。
- 键盘操作、减少动态效果和 2D 降级。
- WebGL 视觉冒烟：四季关键点、朔望和接近日月食对齐条件的日期。

## 13. 迁移方式

改造按模块增量进行，当前页面在新模块可用前保持可运行：

1. 先建立纯计算模块和测试，不改变当前 UI。
2. 引入 `WorldState`，让现有太阳黄经和角度显示改用统一状态。
3. 建立单一 WebGL renderer 与双视口场景。
4. 建立时间控制和三层时间轴。
5. 建立知识卡、地点与 2D 降级。
6. 把二十八宿和本地星表移入进阶面板。
7. 删除旧的重复计算、六十甲子空间连线和远程占位抓取。

每一步保持测试通过。不会在迁移中修改 `tiangan_dizhi_cycle.html`。

## 14. 验收标准

设计实现完成时应满足：

1. 通过 `file://` 直接打开，无网络请求和控制台错误。
2. 桌面同时显示太阳中心和地球中心场景，日期严格同步。
3. 月球轨道倾角、升降交点和月相在两个场景中一致。
4. 公历月份、节气、农历月份和当前指针在时间轴中正确对齐。
5. 默认北京时间，可切换时区和观察地点。
6. 春节和立春两种干支年并列显示，边界差异有解释。
7. WebGL 不可用时仍可使用时间轴和知识卡。
8. 手机端只渲染一个可见场景并可切换。
9. 进阶星空默认关闭，远程占位抓取已移除。
10. 所有自动化测试通过，并完成关键日期的浏览器视觉冒烟检查。
